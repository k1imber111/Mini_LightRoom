## 1. Что это и зачем
Личный локальный проявщик RAW для Ивана (Sony, ARW) с GUI на PySide6. Задачи, которые он поставил:
1. Автоматизировать обработку разных по типу кадров, «одним фильтром плохо получается».
2. **Копирование стиля с чужих фото** (главная фишка).
3. Автообработка, отбор кадров, позже ИИ-обработка.
4. Интерфейс простой, лёгкий, с кнопками, не перегруженный.

**Жёсткие требования:** всё работает локально, без платных сторонних API. Есть ключи DeepSeek, Алиса, GigaChat: их можно использовать только для текстовых команд (см. этап 6), но не для обработки пикселей. Фото никуда не отправляются.

## 4. Что уже сделано (v0.1)
**Движок (`engine.py`)**
- `load_image` (rawpy, `half_size` для превью, 16 бит → float32 RGB 0..1), `load_thumb` (встроенный JPEG из RAW + поворот по `flip`), `sharpness` (дисперсия лапласиана), `save_jpeg`.
- `process(img, params, style, src_stats, local)`: баланс белого + экспозиция в линейном свете, света/тени по маске сглаженной яркости, контраст (smoothstep), чёткость, сочность/насыщенность, стиль, виньетка, резкость. `local=False` отключает пространственные операции (нужно для LUT).
- `auto_params(img)`: экспозиция по медиане яркости (цель 18% серого, с коэффициентом 0.85), света/тени/контраст по гистограмме, **мягкий** баланс белого (±12 / ±8), чтобы закат оставался тёплым.
- Стиль: `style_from_image` → среднее и σ в LAB, перенос по Рейнхарду с ограничением отношения σ в диапазоне 0.5–2; сила задаётся ползунком.
- `export_cube` (3D LUT 33³, только поточечные операции), `export_one` (полный экспорт в процессе), `read_json` / `write_json`.
- SLIDERS: экспозиция, контраст, света, тени, чёткость, температура, оттенок, сочность, насыщенность, резкость, виньетка. Шкалы расширены вдвое (экспозиция ±500 = ±5 EV, остальное ±200, сочность/насыщенность от -100): коэффициенты формул прежние, поэтому старые sidecar и «Авто» выглядят как раньше. Контраст > 100 — вторая S-кривая.
- Просмотр в масштабе: `full_size` (размер из заголовка RAW без проявки), `process(..., frame=)` (вырезка считается как часть целого кадра: размытия и виньетка от полной ширины), `process_region` (видимая область + поля 1/20 ширины под широкие размытия), `style_source_stats` (стиль для вырезки по статистикам всего кадра). Расхождение вырезки с целым кадром ≤ 0.0003.

**Интерфейс (`ui.py`)**
- Три колонки: лента миниатюр (слева), кадр (центр), панель правок (справа) + тулбар.
- Миниатюры в фоне (2 потока), пометка ⚠ «возможно, размыт» (порог: резкость < 0.3 медианы папки, работает при ≥3 кадров).
- Рендер превью в фоновом потоке с «схлопыванием» запросов (`rendering`/`dirty`), гистограмма RGB.
- Авто (`A`), сброс (`Ctrl+R`), до/после (`\`), копировать/вставить правки в выделенные (`Ctrl+C/V`), галочка «Авто для новых кадров».
- Стили с референса (новый стиль из фото, список, сила), сохранение LUT, пресеты (сохранить/применить).
- Экспорт: текущий / выделенные / все, «Авто-тон для каждого кадра», пропуск размытых, длинная сторона, качество, папка; `ProcessPoolExecutor` (до 2 процессов, полный RAW ≈ 1 ГБ памяти), прогресс, отмена, итоговое окно с открытием папки.
- Тёмная тема Fusion. Двойной щелчок по ползунку сбрасывает его.
- Масштаб (`ImageView`): шаги `ZOOM_STEPS` 25…1600% от полного разрешения, колёсико к курсору, перетаскивание, двойной щелчок 100%/вписать, кнопки −/+ и список в тулбаре, Ctrl+=/-/0/1. Когда превью растянуто больше своего размера, в фоне грузится полный кадр (~1 с, держится только для текущего) и через 150 мс после остановки дорисовывается видимая область (`detail_job`, 0.1–0.3 с на 24 Мп). Смена правок сбрасывает деталь (`detail_gen`), до/после работает и в масштабе.

**Пресеты-образы (2026-09-25)**
- `engine.apply_look(img, look, strength)`: баланс белого/экспозиция, HSL по 8 цветам (таблица сдвигов на 360°), насыщенность/сочность, тонирование теней/полутонов/светов (таблица по яркости на 1024 уровня), монотонные кривые Фритча — Карлсона (общая + R/G/B). Всё поточечно → входит в LUT. Сила — линейное смешивание с кадром.
- В `process` образ идёт после стиля, до виньетки/резкости. Параметры `look` (имя) и `look_strength` в params; рецепт передаётся отдельно (`look=`), как стиль.
- 28 пресетов в `looks/builtin.json`, рецепты составлены по открытым разборам (мягкий матовый низ +15…40, опущенная точка белого, контраст мягкой S-кривой, тени в мяту/лаванду 155–275°, света в крем 30–50°, приглушённые зелёные/синие, осветлённый оранжевый).
- UI: группа «Пресеты» (список по группам, миниатюры текущего кадра через `look_icons_job`, подсказка «в духе…»), ползунок «Сила пресета». Старая группа переименована в «Мои пресеты».

**Этап 1: сцены → автопресет (2026-09-25)**
- `scene.SceneClassifier`: open_clip ViT-B-32 `laion2b_s34b_b79k`, fp16 на CUDA, веса в `models/`. Zero-shot по усреднённым эмбеддингам нескольких англ. описаний на сцену; вход — миниатюры ленты 200 px (уже в памяти, без повторного чтения RAW).
- 14 сцен в `scenes.json` (JSON, чтобы не тянуть pyyaml). `engine.scene_preset(img, scene)` = `auto_params` + поправки сцены (с обрезкой по шкалам) + пресет сцены и его сила.
- UI: кнопка «🔍 Сцены» (Ctrl+Shift+S), модель грузится в фоне при первом нажатии и остаётся в памяти; сцена в подписи кадра в ленте; галочка «Пресет по сцене» влияет на «Авто» и авто для новых кадров; в экспорте «Пресет по сцене для каждого кадра» (`job["scene"]`, в `export_one` вместо `auto`). Результаты хранятся в sidecar под ключом `__scenes__`.
- Без torch кнопка объясняет, что запустить `install_ai.bat`; остальная программа работает.

**Этап 2: перенос стиля (2026-09-25)**
- `lab_stats` хранит ещё и 65 квантилей L/a/b; старые стили без `q` работают в мягком режиме.
- `_apply_style(img, style, p, src)`: режим `style_mode` 0 — Рейнхард (отношение разбросов 0.5–2), 1 — сопоставление квантилей через `_transfer_curve` с ограничением крутизны 0.5–2 (без него однородное небо растягивалось в ореол вокруг луны — видно на DSC02894). Сдвиг в LAB мягко ограничен `limit·tanh(shift/limit)` (L 40, a/b 30). Силы раздельно: `style_strength` — цвет (a/b), `style_tone` — L. `style_skin` ослабляет цвет по маске кожи (LAB: оттенок 20–75°, хрома 6–50). Всё поточечно → в LUT.
- `mix_styles(a, b, t)` смешивает среднее, разброс и квантили; параметры `style2`, `style_mix`. `normalize_params` — для старых правок `style_tone = style_strength`.
- UI: миниатюра референса `styles/<имя>.jpg`, меню «⋯» (переименовать с обновлением ссылок в правках папки, удалить с подтверждением), режим, 3 ползунка, второй стиль и доля; LUT «всё вместе / только стиль».
- Проверено на реальных кадрах (референс DSC00052 → луна, парк, портрет, корабль): мягкий и точный режимы естественные, кожа не перекрашивается.

**Этап 3: маски и локальные правки (2026-09-25)**
- Слои в `params["masks"]` (JSON, в sidecar): `linear` (a, b), `radial` (c, r, feather), `brush` (strokes: pts, r, erase; feather), `ai` (cat). Геометрия в долях полного кадра → одна маска для превью, вырезки в масштабе и экспорта (`frame=`). У слоя `on`, `invert`, `adj` (ключи `masks.LOCAL_KEYS`).
- `engine.apply_masks`: для каждого слоя тот же `process` с ползунками слоя, смешанный по маске; после стиля и пресета, до виньетки и резкости; только при `local=True` (в LUT не попадает).
- ИИ: `segment.Segmenter` — `nvidia/segformer-b2-finetuned-ade-512-512` (~110 МБ в `models/`), категории → классы ADE20K по меткам (`CATEGORIES`), края — guided filter по кадру. Вход — превью с авто-тоном. Маска хранится PNG `<папка>/.mini_lightroom_masks/<файл>.<cat>.png` в размере превью (1400 px); массив передаётся в обработку ключом `arr` только в копии (`render_params`), в правки не пишется. Недостающие маски: `ensure_ai_masks` при открытии кадра и `prepare_ai_job` перед экспортом.
- Окно: группа «Маски» (кисть, линейный, радиальный, меню ИИ, список с галочками и переименованием, инверсия, «Показать (O)», размер/ластик/растушёвка, 10 локальных ползунков). `MaskEditor`: жесты на кадре, ручки, курсор кисти; левая кнопка занята маской — кадр двигают правая/средняя. Копирование правок — глубокое (`copy.deepcopy`).
- Ускорение: экспозиция/баланс белого в `process` без возведения пикселей в степень (`x·k^(1/2.2)`), пропуск при нулях.
- Проверено: синтетика (все типы масок, ластик, инверсия, совпадение вырезки с кадром), окно (жесты мышью QTest, ИИ-слой из PNG, подсветка, sidecar, независимость копии), реальные ARW: сегментация 0.3 с/кадр на RTX 4060, небо затемнено без ореолов вокруг снастей и крон, экспорт неоткрытого кадра с досчитанной маской.

**Этап 4: шумодав и увеличение (2026-09-26)**
- `enhance.py`: spandrel собирает архитектуру по весам (без ONNX — torch с CUDA уже стоит). Веса с GitHub-релизов в `models/`: `scunet_color_real_psnr.pth` (KAIR), `RealESRGAN_x2plus.pth`, `RealESRGAN_x4plus.pth`. fp16 на CUDA, тайлы 512 с полями 32 (без швов), `threading.Lock` — одна видеокарта на все потоки окна. Модели кэшируются на процесс.
- Шумодав — к исходнику до `process()` (ключ `denoise` в SLIDERS, `process` его не трогает): в окне превью очищается целиком на полной силе один раз (`denoise_job`, `base_dn`), ползунок только смешивает; в масштабе — `process_region(prep=)` чистит лишь видимую часть +16 px (`_denoise_box`); в экспорте — полный кадр (`export_one`). Увеличение — в `export_one` после длинной стороны (`job["upscale"]` 2/4). При шумодаве/увеличении экспорт идёт в 1 процессе.
- ISO: `enhance.iso_of` (exifread, первые 256 КБ файла), `iso_strength`: <1600 → 0, 1600→30, 3200→50, 6400→70, 12800+→85. Авто при открытии и кнопка «Авто» ставят шумодав по ISO (низкий ISO не сбрасывает ручное значение). ISO в строке состояния.
- Проверено: синтетика (ошибка шума ×40 меньше, нет швов, ×2 даёт вдвое больший размер), окно (ползунок → превью без шума), реальный ARW ISO 800 с тенями +120: сила 60 убирает цветной шум и сохраняет фактуру, 100 — уже гладко. Полный кадр 6240×4168 — 24 с, 0.5 ГБ VRAM; экспорт «шумодав + 1500 px + ×2» → 3000×2004 за 30 с.

**Этап 8 (часть): отмена/повтор, обрезка и горизонт (2026-09-26)**
- История: у каждого кадра стек снимков `params` (deepcopy, до 100). Снимок — через 0.4 с после последнего `request_render` (`history_timer` → `commit_history`), поэтому протяжка ползунка/мазок кисти = один шаг; при смене кадра снимок сразу. Вставка правок пишет шаг и в историю целевых кадров. Только в памяти.
- Геометрия — последний шаг после всех правок: `params["crop"]` ([x0, y0, x1, y1] в долях повёрнутого холста или None) и `params["angle"]` (градусы). `engine.crop_matrix` — матрица «полный кадр → результат»; `apply_crop` (превью в `render_job`, экспорт в `export_one`), `process_view_region` (масштаб: обрабатывает охватывающий кусок полного кадра и поворачивает той же матрицей), `fit_crop`/`crop_valid` (рамка без пустых углов), `aspect_crop`. Маски остаются в координатах полного кадра: `ImageView.to_norm/to_widget_pt` переводят через матрицу.
- UI: группа «Обрезка и горизонт» (пропорции, «↔», «Горизонт» в десятых долях градуса, «Новые кадры — как в камере», «Сброс»), режим «✂ Обрезка» (C) — `CropEditor` вместо редактора масок, показывается весь повёрнутый холст; Enter/Esc активны только в этом режиме. Пресеты («Мои» и применение) обрезку не трогают.
- «Как в камере»: `engine.camera_aspect` по встроенному JPEG. На ARW Ивана: горизонтальный → 6240×3510 (16:9), вертикальный → 3510×6240 (9:16), композиция совпадает с JPEG камеры, экспорт тех же размеров.

**Этап 8 (часть): HSL и тональная кривая (2026-09-26)**
- Параметры `curve` ({"rgb"|"r"|"g"|"b": точки 0..255}) и `hsl` ({цвет: [оттенок, насыщ., яркость]}, ±100). В `process` после сочности/насыщенности: сначала кривая, затем HSL (как в Lightroom), до стиля и пресета; используют те же `_apply_curve`/`_apply_hsl`, что пресеты; поточечно → в LUT.
- UI: группы «Тональная кривая» (`CurveEditor`: гистограмма, точки мышью, двойной щелчок — удалить, концы только по вертикали, каналы, `CURVE_SHAPES`) и «HSL / Цвет» (3 вкладки × 8 ползунков). Словари `curve`/`hsl` при правке заменяются новыми (фоновые задачи держат неглубокую копию params). Отмена работает автоматически.

**Целевая правка, ИИ-цветокоррекция, ИИ-композиция (2026-09-26)** — этап 7 (отбор кадров) Иван отменил.
- Целевая правка: `TargetEditor`; цвет берётся на входе HSL/кривой (`ui.sample_input`: патч превью через params без HSL/кривой/стиля/пресета/масок); HSL — веса `engine.hsl_weights` (треугольники ±45°), drag 0.5 ед./px на открытую вкладку; кривая — точка в тоне под курсором.
- `grading.py`: `analyze` (области SegFormer people→кожа по `_skin_mask`, sky, greenery, water; средние L/C*/h_ab круговым средним, нейтрали для баланса, доминанта и ключ), `variants` (10 правил, см. README). Цвета памяти: эталоны `MEMORY` (кожа 49° h_ab — IS&T CIC / Color Res. Appl. 2023; +1 L*, +2 C*), шаг ≤ 20° h_ab; HSL-значения подгоняются итерациями на среднем цвете области той же `_apply_hsl` (перевод LAB↔HSV нелинеен, «в лоб» кожа перелетала на 9°). Тёмные/бесцветные области (L*<15) не трогаются; до нижней границы хромы — только при L*>35 (иначе тёмная листва «кислотила»).
- `params["ai_grade"]` = {id, name, rule, recipe (для `apply_look`), masks (ИИ-слои), strength}; в `process` рецепт после HSL, до стиля; маски варианта идут в `apply_masks` с `amount`=сила; `protect_white` у неба (солнце не сереет). Окно: «🎨 ИИ-цвет» (G), `grade_job` в фоне (маски/сцена досчитываются, миниатюры 260 px), карусель под кадром, «Сила», пояснение правила.
- Отладка: синтетика (кожа 31°→50°, зелень/небо к эталонам, кадр в эталоне почти не меняется); 44 ARW — 0 ошибок, 0.5 с/кадр (первый ~9 с — модели); заметность ΔE к исходнику 4–12 у художественных вариантов (сначала было 1–4 — усилены), «Естественные» ≈ 2 (это исправление); относительно исходника ни один вариант не добавляет пересвета/«кислоты».
- Композиция: `engine.auto_horizon` (Canny+Hough, горизонтали ±12°, вертикали, граница неба; взвешенная медиана, отказ при разбросе), `subject_point` (верх силуэта главного человека, ≥1.5% кадра), `saliency_point`, `horizon_level` (только 0.2–0.8 высоты), `thirds_crop` (85/75/65%, при догадке по заметности — не меньше 75%). OpenCV 5: `HoughLinesP` возвращает (N,4). На реальных: морские горизонты +0.9°/+0.7°, горизонт на нижней трети, голова на пересечении.

**Зависания при нескольких ИИ-функциях подряд — исправлено (2026-09-26)**
- Причина (воспроизведено скриптом на реальном ARW, стеки через faulthandler): torch вызывался из потоков `QThreadPool`. PySide после каждой задачи уничтожает состояние Python-потока, а torch (pybind11) держит на него указатель: второй вызов torch в том же потоке Qt висел навсегда внутри `torch.load` или ронял процесс `0xc0000374` (повреждение кучи). Без Qt и в обычных потоках Python — не воспроизводится.
- Исправление: `ui.AI_POOL` — `ThreadPoolExecutor(1)`, один постоянный поток Python для всего с torch (сегментация, грейд, сцены, шумодав превью, подготовка к экспорту, деталь с шумодавом); `run_task(..., pool=AI_POOL)`. Модели — одна на программу (`segment.get_segmenter`, `scene.get_classifier`) под общим `enhance.GPU_LOCK`; вызовы моделей под тем же замком.
- Попутно: transformers после загрузки весов `.bin` запускал свой поток, ходивший на HF Hub за конвертацией в safetensors и трогавший torch мимо замка — отключено (`DISABLE_SAFETENSORS_CONVERSION`); SegFormer и CLIP грузятся из `models/` без обращений к сети (`local_files_only`, `try_to_load_from_cache`), сеть — только при первом скачивании. Горизонт и заметность для третей считаются в фоне (раньше — в главном потоке).
- `main.py`: сторож — если окно не обрабатывает события 15 с, стеки всех потоков пишутся в `logs/hang.log`; аварийные падения — в `logs/crash_current.log` (faulthandler); при нормальном выходе он удаляется (faulthandler в Windows пишет и безобидные COM-исключения 0x8001010d), а если запуск оборвался — при следующем старте переименовывается в `crash_<время>.log`.
- Проверка: 6 функций ИИ подряд, пары, 6 кругов с переключением кадров — всё завершается за 12–17 с, окно не замирает дольше 0.3 с. Внимание для тестов: `QTest.qWait` держит GIL и душит рабочие потоки — ждать через `processEvents` + `sleep`.

**ИИ-ретушь: кожа и размытие фона (2026-09-26)**
- Ползунки `retouch` («Ретушь кожи») и `bokeh` («Размытие фона») в `SLIDERS`, группа «ИИ-ретушь»; `engine.AI_SLIDER_CATS` — какая маска ИИ нужна. Массивы приходят в `process` ключом `p["ai_arr"]` (готовит `ui.render_params`, как `arr` у слоёв), только `local=True`.
- `skin_smooth`: частотное разложение — guided filter (r = fw/120, eps 5e-3) + 60% мелкой текстуры; маска = люди × `_skin_mask`. Синтетика: неровность кожи 0.040 → 0.021, край «глаза» сдвигается ≤ 0.03.
- `lens_blur`: σ до 1.2% ширины кадра, размытие на уменьшенной копии, нормированное маской фона — цвет объекта не растекается (красное у края 0.000). Пустая маска объекта — ничего не размывает.
- Маска «subject» (`ui._ai_masks`): `engine.main_people` — самый крупный силуэт (≥1.5% кадра) и сопоставимые с ним (≥40% его площади), без толпы за спиной; иначе `engine.saliency_mask` (уточнение `G.refine`), а пятно меньше 2% кадра — «объекта нет» (пейзаж, город), окно об этом сообщает.
- Реальные ARW: маски 0.43 с/кадр; портрет — кожа ровнее, глаза/волосы резкие, толпа за спиной размыта; на кадре вокзала без крупного человека заметность выбирала крошечное пятно и размывала здание — отсюда порог 2%. Корабль — размыт низ кадра (похоже на тилт-шифт; спорно).
- `ensure_ai_masks` досчитывает маски ползунков в фоне (без дублей — `seg_pending`); экспорт готовит их через `ai_cats`.

**«ИИ-улучшить», ★ и кэш карусели (2026-09-26)**

Применение — один шаг истории (`commit_history` до правок).
- ★: `SceneClassifier.aesthetic` — CLIP, сходство с описаниями удачной обработки минус неудачной; ★ у лучшей миниатюры, оценки в подсказке. На 11 реальных кадрах ★ распределилась по 6 разным вариантам (закаты — «Плотное небо»/сплит), разброс оценок 1–4 — слабый сигнал, поэтому только подсказка.

**Единый цвет серии (2026-09-26)**
- «🎞 Единый цвет» (Ctrl+Shift+M): эталон — текущий кадр, цели — выделенные в ленте (без выделения — вся папка после подтверждения). `ui.match_job` (глобальный пул, без torch) → `engine.match_params` для каждого кадра; результат в sidecar, в истории каждого кадра — шаг (Ctrl+Z на кадре вернёт).
- `match_params`: копирует творческие правки эталона (всё, кроме `PER_FRAME`: обрезка, угол, маски, шумодав; маски ИИ-цвета убираются), старт экспозиции/баланса — от разницы `auto_params` кадра и эталона, затем 5 итераций: у каждого рычага своя мера `match_stats` (экспозиция↔медиана в EV, температура↔b*, оттенок↔a* среднего цвета полутонов с хромой, обрезанной на 40; контраст↔σL* и насыщенность↔C* — с половинным шагом). Пределы `MATCH_VARS` (±150 экспозиции, ±60 баланса, ±25 контраста/насыщенности); рычаг, который во всём пределе меняет меру меньше чем на 2, не трогается.
- Первые версии не годились: совместный `lstsq` по всем рычагам уводил оттенок/насыщенность в пределы, а баланс по нейтралям на закатах скакал (нейтралей почти нет). Реальные кадры: соседние кадры заката — EV совпал до ±0.06, b* +8→+3 / +15→+8.5 (дальше предел температуры); синтетика — −1 EV и тёплый каст убираются полностью, ≈1 с/кадр.
- Ограничение: подгонка честно «усредняет» серию — если выделить разные сюжеты (светлое окно и вечерняя река), светлый кадр потемнеет до эталона.

**Этап 3A: движок оценки брака `quality.py` (2026-10-04)**
- Метод: σ размытия из отношения энергий градиента исходника и копии, размытой σ₀=1 (Zhuo–Sim), по сетке клеток 64 px на ПОЛНОМ разрешении, 4 направления градиента (0/45/90/135°), только пиксели, где крупный масштаб (σ=3) видит край (`coarse_min`). Первый вариант на отобранных краях Canny не годился: при смазе сильно размытые края исчезают из выборки, а оставшиеся резкие делают кадр «нормальным» (ошибка выжившего). σ нормирована на «кадр 6000 px по длинной стороне» (`norm_long_side`) — порог не зависит от разрешения камеры.
- Решение: область, где резкость обязана быть (`rois` — лица, позже; точка АФ Sony из тега `0x2027`, пересчитанная под поворот кадра), иначе «лучшие места кадра» (клетки не хуже 1.5× лучшего блока 256 px; фон боке выпадает). Смаз: анизотропия σ по направлениям ≥ 1.6 и σ самого размытого направления ≥ 1.4, направление — в `angle`; промах фокуса: область мягкая, а лучшее место кадра резкое (σ ≤ 0.9, отношение ≥ 1.7). Второстепенные области сами кадр в «брак» не переводят (максимум «сомнительно»). Мало структуры (небо, туман) → `unknown`, не брак.
- Пороги — `quality.json` (σ: сомнительно ≥ 1.15, брак ≥ 1.7; смаз 1.4 / 2.0). Калибровка на 44 реальных ARW: оригиналы — 42 «ok», 2 «сомнительно» (обе луны на 350 мм, мягкие по природе, видно глазами), «брак» 0; σ кадров p50 0.66, p90 0.87, max 1.20. Искусственный брак на 11 кадрах: Гаусс σ3 — 11/11 «брак»; σ1.5 — 8/11 замечены (2 «брак», 6 «сомнительно»); σ1.0 — 5/11 «сомнительно»; смаз 10–20 px — около 80% замечено, тип «смаз» определяется верно. Время ≈ 3 с на кадр 24 Мп (3 потока: 44 кадра с 10 вариантами за 183 с).
- Тесты: `tests/test_quality.py` (синтетика 6000×4000: расфокус монотонно растёт, смаз 0/30/90/150° — тип и направление, боке не брак, промах фокуса, АФ-точка, второстепенная область, небо без краёв, пересчёт ориентации, файл с кириллицей).
